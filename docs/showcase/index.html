Why it matters

Three times everything was green and the page was wrong.

This repository is not a template. It is the record of a pipeline that shipped defects behind passing checks three times, and of the guardrail added each time so the same class of defect cannot pass again.

01 · shipped

A green band nested inside another green band

18 sections validated · build ✓ · tests ✓

Figma assets were cropped by declaring each node's size. Two declared sizes were wrong, so the crop returned a different region of canvas and shipped it as the asset. The manifest validated, the unit tests passed, the static export succeeded — nothing compared a browser render against the design.

“Verify the render, not the diff.”

02 · near miss

A CMS migration that would have been green while disconnected

131 unit · 23 e2e · 11 fidelity ✓

Phase 2 moved every string into Payload and finished green. But the seed wrote into the database exactly the strings the components had hardcoded, so each check compared one source against an identical copy of the other. The claim the migration existed to make had no check behind it at all.

“Prove the seam, not the render.”

03 · shipped to production

Thirty-four images, all 500, behind four green checks

local build ✓ · CI ✓ · evidence pack ✓

Payload's media collection had no storage adapter, so uploads landed on the runner's gitignored disk. The media rows survived in the remote database; the files did not survive the deploy. Every existing check ran on the machine that held the files, so none of them could see it.

“A check that cannot confirm what it looked at says so, once.”

The outcome

Deployed, and checked against the deployment.

The last gap closed on 22 August: media served from blob storage, and the three-way parity report agreeing across the Figma references, the local render and production.

Documentation · v0.1.0

How it was built, in the order it happened.

A monorepo on Bun: one site, three skills. Sections below mirror the repository — architecture, the three checks, the pull requests, the decision records, how to reproduce it, and the blind spots that remain.

01 · Architecture

One manifest, three derived artefacts.

site.manifest.json is human-reviewed and load-bearing: the React section components, the Phase 1 content seed and the Payload config all derive from it. No content model is authored twice, and check:cms-drift fails CI if the committed config stops matching the manifest.

Stack

Next.js App Router with Tailwind v4, Payload CMS in the same repository (ADR-0001), SQLite locally and Turso libSQL in production, Bun as package manager and script runner with Node.js as the runtime (ADR-0006). Node is pinned to >=20.9.0.

The phase seam

getGlobal / getCollection in lib/content.ts return locale-resolved, unsuffixed objects, so components never learn which backend serves them. Phase 2 replaced those two function bodies and deleted the JSON reader — no component changed.

Localization

Payload's native localization, with the _en suffix used only as an interchange format in the seed files (ADR-0005). fallbackLocale: 'en', and the manifest schema rejects field names that already carry a locale suffix.

02 · The three checks

Each is verified in the failing direction.

A detector that has only ever seen clean input is not known to detect anything. Each check below is proven by breaking the thing it watches and requiring red.

Check 1 — design fidelity, on two axes

Not a pixel diff and not a screenshot baseline: both of those grade the render against a previous render. One axis compares each section's rendered aspect ratio against a number taken off the design; the other compares coarse block colour against a reference PNG that refs.json explicitly vouches for. A reference nobody vouched for withholds the content axis and keeps the aspect axis — ADR-0008. 

$ bun run verify:design      # needs a dev server
$ bun run e2e                # one fidelity test per section, in Playwright
$ bun run --cwd apps/web check:assets
                             # the chrome detector, applied to committed images

Check 2 — the CMS round trip

apps/web/e2e/cms-round-trip.spec.ts writes through the admin UI a value that exists nowhere in the repository, then requires it both on the rendered page and in the server's HTML. It is the only check that can tell a database read from a string literal. Hardcode the headline back into the component and it must go red. 

admin UI ──writes a value no fixture contains──> Payload ──> lib/content.ts ──> page
                                                                                │
                        required on the page and in the server's HTML ───────────┘

Check 3 — the deployment, after the fact

bun run evidence runs entirely on your machine, so it cannot see a difference that exists only on the host — which is exactly how the media defect shipped behind four green checks. bun run parity-report asks the Figma references, the local server and the deployment the same questions over HTTP and writes parity-report/report.html: each section's reference, local render and deployed render side by side, plus what loaded and what did not. It exits non-zero on a disagreement.

.github/workflows/parity.yml runs it manually and on a schedule — deliberately not on push, because a run against a URL that has not been redeployed yet would report the previous deployment's state as this commit's.

#4merged21 Aug +1,741−4852 files
Eval the skill's judgement, not only its code

48 tests proved the code behaves. Nothing proved the skill's decisions were right.

Ten reasoning cases

  • Every guardrail in src/ exists because a judgement went wrong first: a size believed because a crop succeeded; a Figma dimension badge painted out instead of read as evidence; a wrong-shaped section diagnosed as a bad capture when it was a padding bug; a CSS max-width mistaken for the design's rendered width
  • All cases are pure reasoning — allowed_tools: [], no network, no Figma seat — and carry the real node ids and numbers, so generic design advice cannot satisfy them
  • Every case carries at least one deterministic grader beside its LLM judge, so no case rests on a vote on prose

The suite is checked even though it cannot be run here

  • claude plugin eval is early access, so on this machine it exits before reading a case. 24 structural tests assert instead that every prompt loads, every grader is well-formed, every regex compiles, no case is judge-only, and an empty suite fails.

A suite that cannot run is not coverage. Test the suite until it can.

#6merged22 Aug +2,386−3854 files
The CMS step as a second skill, with evals for its judgements

131 unit tests, 23 e2e tests, 11 fidelity comparisons — every one of them green with the CMS disconnected.

The argument

  • A fidelity defect is visible; a broken CMS seam is indistinguishable from success. The page renders the right words whether it read them from the database or from a string literal three lines above.
  • The seed wrote into Payload exactly the strings Phase 1 had hardcoded, so every check compared one source to an identical copy of the other.

Eleven eval cases, from eleven real incidents

  • A hydration mismatch on /admin dismissed because the panel worked
  • A translatable flip that is really a data migration
  • A secret that fell back silently in production
  • The round trip racing the fidelity suite it was added to
  • An evidence pack that remembered “static export” after the export was removed
  • A format gate blamed for a violation it was correctly reporting

Grader design

  • A keyword match cannot read polarity — contains: collection is satisfied by “use a collection” and by “a collection is overkill” alike. So deterministic graders assert positive evidence of the right decision, and every requirement that turns on direction is carried by the judged grader. The structural test requires both kinds on every case.
  • Four cases put a correct artefact to the agent and grade what it fails to say — the hardest to grade and the likeliest to be passed by an agreeable answer.
  • No src/: the code here would be project-specific, so the skill ships judgement only (ADR-0012).

Only a value that exists nowhere in the repository can tell a database read from a string literal.

#7merged22 Aug +841−527 files
Fresh-machine Vercel deployment skill with evals

Written from the live deploy, including the part where a green build proved nothing.

Seven steps

  • Install and authenticate the CLIs — the user does the interactive login; the agent never receives a token
  • Link the project; provision and check the hosted database — a newly created one has zero tables, so push schema and seed before trusting it
  • Set env vars, then vercel deploy --prod rather than a stale vercel redeploy
  • Verify with curl and a database-backed row count, then write down what was learned

Six eval cases, each from a real error in this repository's own incident

  • A blank env var treated as harmless; a green build treated as proof
  • A stale redeploy after changing env vars; “point it at the bundled file to go green”
  • Handing an agent a raw token; declaring an empty remote database live

A deployment is verified when something outside your machine answers a question you did not cache.

#8merged22 Aug +2,154−7327 files
Guard media on Vercel Blob storage and add a three-way parity check

Both environments returned byte-identical section markup. All 34 images on the deployment returned 500.

Root cause

  • Payload's media collection used upload: true with no storage adapter, writing binaries to the gitignored apps/web/media/. Rows survived in the remote Turso database; the files stayed on the machine that ran the seed — invisible to every existing check, because they all run on that machine.

Decisions, taken deliberately

  • @payloadcms/storage-vercel-blob over committing media/ or reverting to static public/ paths — the CMS must be able to replace an image
  • A production build without BLOB_READ_WRITE_TOKEN now throws, mirroring PAYLOAD_SECRET, so a deployment that would serve broken images fails to build instead
  • CI and the evidence pack therefore pass a placeholder token — honest for a build that never uploads a file, and the resulting blind spot is written into the evidence pack's own “what this does not cover” section rather than hidden
  • parity-report is deliberately separate from evidence and fetches the deployment over HTTP; its workflow is not on push, because a URL that has not been redeployed yet reports the previous deployment's state as this commit's
  • The report shows screenshots of all three sources side by side, because a status table only knows whether things loaded — a row can pass every check and still look wrong
  • The duplicate media rows are deferred with the reason recorded, and the mechanism labelled undiagnosed rather than guessed at

Setting the token does not repair existing rows: uploadImage reuses a row it finds by sourcePath, so the pre-blob rows are exactly the ones a reseed skips. Clear the collection first.

05 · Reproduce

Clone to running site.

Every root command delegates to the workspace that owns it, so the names work from either place. docs/reproduce.md is the long version, one section per skill in the order they were run, including which steps cannot run in CI and why.

239 unit tests is the root bun run test: 61 in apps/web, 95 in figma-to-site, 57 in site-to-cms, 26 in deploy-to-vercel. The evidence pack on a pull request reports 156 — it counts only the two workspaces a change to the site can break. Neither figure is the other's correction.

bun run dev          # the site at http://localhost:3000, /admin included
bun run test         # the site's suite and all three skills' suites

bun run --cwd apps/web gen:cms   # payload.config.ts from site.manifest.json
bun run --cwd apps/web seed      # content/*.json into Payload
Gates and evidence
Command What it does
bun run validate:manifest Validates site.manifest.json against its Zod schema
bun run lint Lints the site
bun run build Production build — Payload's /admin and API routes are server-rendered, not exported
bun run verify:design Compares the running page against the Figma references — needs a dev server

06 · Blind spots

What these checks cannot see.

Kept because deleting it turns a pass into a claim nobody made. If you add a check to this repository, add its blind spot too — ADR-0011.

  • Typography, spacing and colour beyond coarse blocks. The fidelity axes are aspect ratio and block colour. A wrong font weight, a 4px padding error, or a slightly wrong shade passes. apps/web/TOKEN-GAPS.md lists the literals not bound to a Figma variable.
  • Anything that only exists on the host. bun run evidence runs on your machine. The media defect shipped because of exactly this, and only parity-report against the production URL closes it.
  • Blob uploads in CI. CI and the evidence pack pass a placeholder BLOB_READ_WRITE_TOKEN. That is honest for a build that never uploads a file, and it means CI never exercises a real upload.
  • The eval suites' own execution. claude plugin eval is early access, so what runs in CI is the suites' structure: every prompt loads, every grader is well-formed, no case is judge-only. Whether an agent passes them is not asserted here.
  • Duplicate media rows. Two rows (header-30.png and logo-190.png) are deferred with the mechanism labelled undiagnosed rather than guessed at.
  • This page. It is a static document generated from the pull requests, the ADRs and a test run — not a live dashboard. The numbers are true as of 22 August 2026 at bc36f77 plus the open #9.
