# ADR-0002: Generate components, seed content, and CMS schema from one manifest

## Status
Accepted

## Date
2026-08-21

## Context
Three artifacts describe the same content model: React section components, the
Phase 1 content files, and the Phase 2 Payload config. Authoring them separately
guarantees drift — a field renamed in one place silently disagrees with the other
two, and the disagreement surfaces at runtime rather than at build time.

## Decision
A single reviewed artifact, `site.manifest.json`, is the source of truth. It
lists sections, their fields, field types, and a `translatable` flag. Three
generators consume it: component scaffolding, the `content/*.json` seed, and
`payload.config.ts`. None of the three is hand-authored.

The manifest is generated by the extraction agent and then **reviewed by a human
before any generator runs**. This is the only human gate in the pipeline, placed
there because a wrong field name propagates into all three artifacts at once —
cheap to fix in one file, expensive to fix in three.

## Alternatives Considered

### Hand-author each artifact, keep them in sync by review
- Pros: no generator to build or maintain
- Cons: drift is a matter of when, not if; the failure is silent
- Rejected: this is precisely the knowledge duplication a single representation
  eliminates

### Derive the CMS schema from the components (parse JSX for content props)
- Pros: no separate manifest file to maintain
- Cons: requires parsing generated code to recover intent that was known
  explicitly one step earlier; brittle against any refactor of component shape
- Rejected: throws away structured information, then pays to guess it back

### Derive everything directly from Figma on each run
- Pros: no intermediate artifact at all
- Cons: no reviewable checkpoint, and design edits would silently restructure the
  CMS schema — including destructive changes to fields holding live content
- Rejected: the review gate is the point

## Consequences
- Adding a field is a manifest edit plus a generator run, never a three-file edit.
- Generators must be idempotent; a zod schema validates the manifest, and CI
  fails when the emitted config disagrees with it.
- The manifest is the artifact an agent reasons about, which keeps the reasoning
  surface small and structured.
